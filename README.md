# QR Studio

מחולל קודי QR מעוצבים, בעברית מלאה. מדביקים קישור, בוחרים עיצוב וגודל, ומורידים תמונה או PDF.
הכול רץ בדפדפן — הקישור, הלוגו והתמונות לא נשלחים לשום שרת.

## מה יש בפנים

- **10 סוגי תוכן** — קישור, טקסט, WiFi, וואטסאפ, כרטיס ביקור (vCard), טלפון,
  אימייל, SMS, מיקום ואירוע ביומן. כל סוג עם טופס משלו ובקידוד לפי התקן.
- **15 עיצובים מוכנים** — מקלאסי שחור-לבן ועד גרדיאנטים זורמים, ניאון וזהב על שחור.
- **התאמה מלאה** — 10 צורות מודול, 6 מסגרות עיניים, 6 מרכזי עיניים, צבעים וגרדיאנטים,
  גודל מודולים, עיגול פינות, שוליים ורמת תיקון שגיאות.
- **לוגו במרכז** — עם פינוי מודולים אוטומטי מתחתיו והעלאת רמת תיקון השגיאות.
- **הסרת רקע אוטומטית מהלוגו** — בשלוש עוצמות, בדפדפן, בלי שרת ובלי מודל.
- **צבעים מהלוגו** — חילוץ פלטת המותג מהקובץ שהועלה, בהתאמה אוטומטית לניגודיות.
- **הגרלת שילוב** — צורות וצבעים אקראיים, מוגבלים לתחום שנשאר סָריק.
- **כיתוב מתחת לקוד** — בחמישה סגנונות מסגרת שמותאמים אוטומטית לעיצוב שנבחר.
- **17 גדלים נפוצים** — דיגיטל (256–4096px), הדפסה ב‑300DPI (2–15 ס״מ), ורשתות
  (פוסט אינסטגרם, סטורי, כרטיס ביקור, פלייר A5, כרזת A4).
- **ייצוא** — PNG, JPG, SVG ו‑PDF; שיתוף ישיר דרך תפריט המכשיר; העתקה ללוח.
- **הורדת רקע** — ייצוא הקוד בלבד, עם שקיפות, להנחה על עיצוב קיים.
- **בדיקת סריקה אמיתית** — כל קוד מפוענח בחזרה לפני שהוא מוצג כתקין (ראו למטה).
- **כרטיסיות מעוצבות** — 10 תבניות בשלוש משפחות: שלטי "סרקו אותי" (שולחן מסעדה,
  חלון ראווה, עמדה), כרטיסי ביקור, ומדבקות. שדות מוכנים, גרירת הקוד, וייצוא
  בגודל פיזי מדויק. שדה ריק מצויר כדוגמה שקופה שלא יודפסת.
- **ייצור באצווה** — רשימה או CSV → גיליון מדבקות A4 עם קווי חיתוך, או ארכיון ZIP.
- **קודים דינמיים** — החלפת יעד אחרי הדפסה ומדידת סריקות (דורש הפעלה, ראו `SETUP.md`).
- **PWA** — התקנה למסך הבית ועבודה מלאה במצב לא‑מקוון.
- **מצב כהה** מלא, RTL אמיתי, ותמיכה ב‑`prefers-reduced-motion`.

## ארכיטקטורה

הרעיון המרכזי: **מקור גאומטרי אחד, שני רנדררים.**

```
טקסט ──► encode.ts ──► מטריצת מודולים
                            │
                            ▼
                      geometry.ts  ──► QrGeometry (נתיבי SVG ביחידות "מודול")
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
     render/svg.ts                 render/canvas.ts
   (תצוגה חיה + ייצוא SVG)      (ייצוא PNG / JPG / PDF)
```

`QrGeometry` מתאר את הקוד כנתיבי וקטור ביחידות מודול — בלי פיקסלים ובלי DOM.
שני הרנדררים מקבלים בדיוק את אותם נתיבים ואת אותם אזורי גרדיאנט, ולכן **מה
שרואים על המסך זהה למה שיורד כקובץ**, ואותה גאומטריה נשארת חדה ב‑256 פיקסל
ובכרזת A4 כאחד.

| קובץ | תפקיד |
|------|-------|
| `src/lib/qr/encode.ts` | קידוד טקסט למטריצת מודולים |
| `src/lib/qr/paths.ts` | בוני נתיבי SVG (`d`) — ריבוע, עיגול, מעוין, ניצוץ, פילֶה קעור… |
| `src/lib/qr/geometry.ts` | מטריצה + עיצוב ← גאומטריה מלאה |
| `src/lib/qr/presets.ts` | 15 העיצובים |
| `src/lib/qr/render/*` | רנדרר SVG ורנדרר Canvas |
| `src/lib/pdf.ts` | כותב PDF מינימלי (ראו למטה) |
| `src/lib/contrast.ts` | בדיקת ניגודיות WCAG לצורכי סריקה |
| `src/lib/verify.ts` | פענוח חוזר של הקוד שנוצר |

### למה PDF בכתיבה עצמית

ספריות ה‑PDF הנפוצות גוררות `html2canvas` ו‑`DOMPurify` — יותר מ‑600KB — בשביל
יכולות שלא בשימוש כאן. `src/lib/pdf.ts` כותב עמוד יחיד עם תמונה אחת בכ‑170 שורות,
עם דחיסת FlateDecode ללא אובדן (חשוב: ארטיפקטים של JPEG סביב קצוות חדים פוגעים
בסריקה). התוצאה: 2.3KB במקום 400KB.

## איך נשמרת הסריקוּת

עיצוב יפה שלא נסרק הוא באג. שלוש שכבות הגנה:

1. **גאומטריה** — צורות "רזות" (ניצוץ, צלב, מעוין) מנופחות במקדם קבוע כדי שהמודול
   יישאר כהה מספיק; קיטום העיניים מוגבל כדי לא לשבור את יחס 1:1:3:1:1 שסורקים
   מחפשים; גלגל העין לעולם לא גולש אל טבעת ההפרדה.
2. **ניגודיות** — `contrast.ts` בודק יחס ניגודיות WCAG בין הקוד לרקע (סורק ממיר
   את הפריים לבהירות, ולכן שני צבעים "שונים" יכולים ליפול על אותה בהירות).
   מתחת ל‑4.5:1 מוצגת אזהרה, מתחת ל‑3:1 אזהרה חמורה.
3. **פענוח חוזר** — `verify.ts` מרנדר את הקוד ב‑480px (רזולוציה של פריים מצלמה)
   ומפענח אותו בחזרה, דרך `BarcodeDetector` המובנה או `jsQR` כגיבוי. התוצאה
   מוצגת למשתמש מתחת לתצוגה המקדימה.

### בדיקות רגרסיה

```bash
npm test                       # 222 בדיקות יחידה על המודולים הטהורים

npm run dev                    # פורט 5174 — נדרש ל-scan/content/logo/batch-scan
npm run test:scan              # כל עיצוב × 2 וריאציות × 3 גדלים, מפוענח בחזרה
npm run test:content           # 10 סוגי התוכן: קידוד לפי התקן + פענוח חוזר
npm run test:logo              # הסרת רקע: רקע נעלם, לוגו נשאר, חור פנימי שורד
npm run test:palette           # חילוץ פלטה: בלי אפורים, והכול עובר את סף הניגודיות
npm run test:batch-scan        # כל צפיפות בגיליון, ברזולוציה שמצלמה קולטת בגודל הזה

npm run build && npm run preview   # פורט 4173
npm run test:export            # כל פורמט ייצוא מפיק קובץ תקין
npm run test:batch             # ייצור באצווה: הגיליון נפתח כ-PDF, הארכיון כ-ZIP
```

בדיקות הדפדפן משתמשות ב-`scripts/browser.mjs`, שנותן ל-Playwright לאתר את
Chromium בעצמו ורק בנפילה מחפש דפדפן מותקן מראש תחת `PLAYWRIGHT_BROWSERS_PATH`.
אפשר לכפות נתיב עם `PW_CHROMIUM_PATH`.

הכול רץ אוטומטית ב-GitHub Actions (`.github/workflows/ci.yml`) על כל דחיפה.

`test:scan` מפענח בשני מסלולים:

- **מצלמה** — הקוד מרונדר **ישירות** ב‑480px, הרזולוציה שבה סורק אמיתי עובד.
  זה השער. רינדור ישיר ולא הקטנה של תמונה גדולה, כי הקטנה מכניסה מוארה מול
  רשת המודולים שמשתנה בין גרסאות דפדפן — ואז הבדיקה נכשלת על ארטיפקט של
  עצמה במקום על חולשה בעיצוב. כאן הפלט נגזר מהווקטורים ולכן זהה בכל סביבה.
  כרגע: **30/30**.
- **מקורי** — בגודל הייצוא עצמו. אינפורמטיבי בלבד: `jsQR` מבצע בינריזציה
  בבלוקים של 8×8 פיקסלים, ובקוד של 2048px בלוק שלם נופל בתוך מודול יחיד
  והסף המקומי מתבלבל. קוד שנקרא ב‑480px ייקרא בוודאי ב‑1024px בכל סורק אמיתי.

## סוגי תוכן

`src/lib/qr/content.ts` מתאר כל סוג כדאטה — שדות, פונקציית קידוד ותקציר — ולכן
הטופס הוא רנדרר גנרי אחד ולא עשרה טפסים כתובים ביד. להוספת סוג חדש מספיק להוסיף
רשומה למפה.

הקידוד עוקב אחרי התקנים: `WIFI:` עם בריחת תווים ל‑`\ ; , : "`, vCard 3.0,
`SMSTO:` (הפורמט שסורקים מזהים בעקביות, בניגוד ל‑`sms:`), `geo:` ו‑`VEVENT`.
מספרי טלפון ישראליים מנורמלים אוטומטית מ‑`05X` ל‑`9725X`.

## הסרת רקע מלוגו

`src/lib/logo/removeBackground.ts` — שלוש החלטות שקובעות את האיכות:

1. **מילוי משטח מהשוליים, לא התאמת צבע גלובלית.** מחיקת כל פיקסל לבן הייתה
   מוחקת גם טקסט לבן בתוך עיגול כהה. המילוי מתחיל מקצוות התמונה ולכן נוגע רק
   ברקע שמחובר לשוליים.
2. **קצה רך** — שקיפות חלקית לפי מרחק מצבע הרקע, אחרת נוצרות מדרגות מרובעות.
3. **ביטול השזירה בקצה** — פיקסל שהיה מעורבב עם לבן נשאר בהיר מדי גם כשהוא
   חצי-שקוף, ויוצר הילה. מחשבים בחזרה: `c = (c_נצפה − רקע × (1 − α)) / α`.

כשלא מזוהה רקע אחיד לא נעשה דבר, ומוצגת הודעה — עדיף מלחורר את הלוגו.

## צבעים מהלוגו והגרלה

`src/lib/logo/palette.ts` מחלץ את **צבעי המותג**, לא "הצבעים בתמונה": פיקסלים
שקופים, אפורים חסרי רוויה, וגוונים שנבלעים ברקע — כולם מסוננים. הגוונים
שנותרים מפוזרים על גלגל הצבע כדי שחמש ההצעות לא יהיו חמישה גוונים של אותו כחול.
צבע שלא עובר את סף הניגודיות אינו נפסל אלא מותאם — **מוכהה מול רקע בהיר,
מובהר מול רקע כהה**.

`src/lib/qr/shuffle.ts` מגריל צורות וצבעים מתוך טווח שנבדק מראש: שתי עצירות
הגרדיאנט נבדקות מול הרקע (סורק ממיר לבהירות, ולכן עצירה בהירה אחת שוברת את
הקוד), וגודל המודול לא יורד מתחת ל‑0.85. הבדיקה מריצה 400 הגרלות ומוודאת
שכולן עומדות בסף.

## כרטיסיות

`src/lib/cards/` — הכרטיס מתואר כדאטה ביחידות **אחוזים מרוחב הכרטיס**, לא
בפיקסלים. אותה החלטה שמאחורי מנוע ה‑QR: תיאור בלתי תלוי ברזולוציה מאפשר לרנדר
את אותו כרטיס בתצוגה מקדימה קטנה ובקובץ הדפסה ב‑300DPI, מאותו מקור.

**מנוע רינדור אחד.** גם התצוגה וגם הייצוא נמשכים על Canvas. אפשר היה לצייר את
התצוגה ב‑HTML ואת הייצוא ב‑Canvas, אבל אז פריסת הטקסט הייתה מחושבת פעמיים בשני
מנועים, והכרטיס שיורד היה נבדל מזה שעל המסך.

הטופס מבוסס שדות מוכנים ולא תיבות חופשיות: מי שמכין כרטיס ביקור חושב במונחי
"שם" ו"טלפון", לא במונחי "אלמנט טקסט במיקום 8,20". מיקום הקוד וגודלו נשארים
בשליטה ידנית, כי שם באמת יש טעם אישי.

## עיצוב

**Mobile‑first, פשוטו כמשמעו.** יש פריסה אחת בלבד — עמודה ממורכזת ברוחב 30rem —
והיא נבנתה קודם כול לאגודל. במסך רחב היא נשארת אותה עמודה; אין מסלול דסקטופ נפרד
שמתכווץ למובייל, כי בדיוק שם נולדים ממשקים שלא מרגישים כמו אפליקציה.

שני עקרונות מכתיבים את השאר:

1. **מונוכרום + צבע אחד.** הבסיס אפור‑לבן ניטרלי; סגול מופיע רק כדי לסמן בחירה.
   קוד ה‑QR הוא הצבע על המסך — הממשק לא מתחרה בו.
2. **גבולות במקום צללים.** עומק נוצר מהיררכיית משטחים וממרווחים.

### המבנה

המסך הראשי מציג רק את הקלט, את הקוד, ואת מה שנבחר. כל קבוצת הגדרות יושבת
מאחורי שורה אחת שפותחת **גיליון תחתון** (`components/ui/Sheet.tsx`) — נגרר
לסגירה, ננעל על גלילת הרקע, ונסגר ב‑Escape. במסך רחב אותו רכיב הופך לחלון ממורכז.

**אין מחוונים.** ערכים רציפים (גודל מודול, עיגול פינות, שוליים) נחשפים כקבוצות
בדידות ב‑`lib/qr/options.ts`: בטלפון בחירה מתוך שלוש אפשרויות מוגדרות מהירה
ומדויקת יותר מגרירה עם האגודל, והערכים עצמם מוגבלים לטווח שנשאר סָריק.

### תנועה

כל ההנפשות נשענות על `lib/motion.ts` — קפיצים לתנועה במרחב, easing לדעיכות,
טווח 150–350ms. סמני בחירה נעים עם `layoutId` במקום להיעלם ולהופיע. הכול מכבד
`prefers-reduced-motion`.

הטיפוגרפיה: **Rubik** לכותרות, **Heebo** לגוף — שתיהן בעלות כיסוי עברי מלא.
